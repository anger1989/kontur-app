# Заметки

Хранилище — обычная папка с markdown-файлами (по умолчанию
`~/Documents/Kontur Vault`). Всё, что пишет агент, пользователь видит в окне
Заметок и может править руками.

```
notes_search { query, limit? }               поиск по содержимому и названиям
notes_read   { path }                        `Папка/Заметка.md` или просто `Заметка`
notes_write  { path, content, mode }         mode: replace | append
notes_create { path, content? }              без content — шаблон с заголовком
notes_delete { path }
```

`path` принимает и путь с расширением, и просто название. Несуществующую
заметку `notes_write` создаёт сам.

## Правила записи

1. **`append` по умолчанию.** `replace` переписывает файл целиком — заметки
   пользователь ведёт руками, и потерять его текст легко. Перед `replace`
   прочитай заметку и убедись, что сохраняешь нужное.
2. **Дата в журнальных записях.** Дописывая в журнал, начинай блок с
   заголовка с датой — иначе через неделю не разобрать, что когда.
3. **Связи.** В хранилище работают вики-ссылки `[[Название заметки]]` —
   ими удобно сшивать конспект встречи с проектом или задачей.
4. **Удаление — по явной просьбе.** `notes_delete` не спрашивает
   подтверждения и не кладёт файл в корзину.

## Типичные сценарии

**Конспект встречи:** `notes_create` с датой в названии, внутри — участники,
решения, задачи. Задачи из конспекта превращай в `todos_create` или Jira —
и поставь в заметке ссылку на созданное.

**Рабочий журнал:** `notes_write` с `mode: append` в одну заметку на неделю
или месяц.

**«Что я писал про X»:** `notes_search` по ключевым словам, потом
`notes_read` найденного — выдержки из поиска обрезаны.

**Дежурства:** в автоматизациях есть шаг `notes.read` + `duty.resolve`,
которые разбирают заметку с графиком дежурств (см. скилл
`kontur-automations`). Формат такой заметки менять осторожно — на него
завязан сценарий.
