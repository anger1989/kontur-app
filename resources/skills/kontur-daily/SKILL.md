# Разбор дня

Один инструмент собирает всё сразу:

```
kontur_my_day   → элементы: kind (task | review | message | mail | event | todo),
                  env, title, state, url, preview (у писем)
todos_list      → личные дела со сроками
```

`kontur_my_day` читает локальную базу синхронизации — там то, что Kontur
успел забрать. Если в ответе подозрительно пусто, скажи об этом: возможно,
контур не поднят и синхронизация не прошла, а не «дел нет».

## Как собирать сводку

1. `kontur_my_day` и `todos_list` — одним заходом.
2. Сгруппируй по смыслу, а не по сервисам:
   - **Ждут меня** — ревью, задачи в статусе на мне, прямые упоминания.
   - **Сегодня по времени** — встречи (`kind: 'event'`) и дела со сроком
     сегодня, по возрастанию времени.
   - **Почта** — непрочитанное, свёрнутое по отправителям и темам; рассылки
     одной строкой.
   - **Шум** — остальное, одной строкой с количеством.
3. Ограничь объём: 5–7 пунктов в каждой группе, дальше «и ещё N».
4. Детали подтягивай точечно: полное письмо — `mail_read`, карточка PR —
   `bitbucket_get_pr`, задача — `jira_search` по ключу.

## Что предлагать

К каждой группе — одно конкретное действие, а не список возможностей:
«рассылки Jenkins (14 писем) — завести правило в папку CI?»,
«PR ABC/payments#42 висит третий день — посмотреть диff?».

Действия не выполняй заранее. Перемещение писем, комментарии, апрувы,
сообщения в каналы — после «да» от пользователя. Исключение — то, о чём
просили прямо в этом же сообщении («разбери и разложи рассылки по папкам»).

## Итоги дня

Для вечерней сводки то же самое плюс:
- что закрылось: `todos_list { includeDone: true }` за сегодня;
- что осталось и переносится на завтра — предложи передвинуть срок
  (`todos_update { todo, dueAt }`);
- если пользователь ведёт журнал в заметках — допиши блок через
  `notes_write { mode: 'append' }` (см. скилл `kontur-notes`).
